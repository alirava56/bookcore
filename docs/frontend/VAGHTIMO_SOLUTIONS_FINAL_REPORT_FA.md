# گزارش تحویل صفحات تخصصی راهکارهای وقتیمو

## خلاصه

چهار صفحهٔ فارسی و راست‌به‌چپ برای مدیران باشگاه‌ها، استودیوهای یوگا و پیلاتس، آکادمی‌ها و مجموعه‌های آبی پیاده‌سازی شد. هر صفحه مسئلهٔ همان مجموعه، نمای تخصصی محصول، یک سناریوی نمونه، مسیر مشتری، پنج پرسش متداول و دموی همان صنعت را دارد. کارت‌های راهکار صفحهٔ اصلی به صفحات جدید وصل شده‌اند.

## ممیزی و اعتبارسنجی محصول

- فرانت‌اند از Next.js App Router، React، فونت وزیرمتن، توکن‌های CSS و آیکون‌های Lucide استفاده می‌کند. هدر، فوتر، Dialog دمو، Accordion، Container، SectionHeading، ButtonLink و نشان موجود برند بازاستفاده شدند. [معماری بک‌اند](../architecture/BACKEND_STRUCTURE_FA.md)
- نقطهٔ شروع سایت عمومی یک صفحهٔ معرفی با دموی محلی بود. اطلاعات سئو از متغیر محیطی دامنه برای صفحهٔ اصلی خوانده می‌شد. روتر عمومی برای صنایع، Sitemap و Robots اختصاصی در سورس وجود نداشت.
- در کنترلر و DTO زمان‌بندی، تعریف و انتشار جلسه همراه با شعبه، خدمت، مربی، سالن، بازه و سقف ظرفیت بررسی شد. فهرست عمومی جلسات منتشرشده از مسیر API پشتیبانی می‌شود. نقش‌های مجاز به فهرست‌های شعبه، منابع و اعضا دسترسی دارند. [API پیاده‌سازی‌شده](../api/implemented.openapi.json)
- ثبت، مشاهده و لغو رزرو به حساب و مجوز وابسته‌اند. ظرفیت رزرو در منطق سرویس کنترل می‌شود. API گزارش اشغال ظرفیت نیز در سورس وجود دارد. نمایش عمومی محصول با دادهٔ فرضی اجرا می‌شود. [تعریف گزارش اشغال ظرفیت](../reporting/OCCUPANCY_REPORTING_FA.md)
- جهت‌گیری محتوا بر نیت جست‌وجوی مدیر مجموعه استوار است. در نمونه‌های فارسی، نیازهای «زمان و ظرفیت کلاس» و «زمان‌بندی فضای ورزشی» در صفحات محصول جدا از مسیر رزرو مشتری ارائه می‌شوند. حجم و سختی کلمات جست‌وجو اندازه‌گیری نشده است. [مدیریت کلاس در Vitrinio](https://vitrinio.app/fa/help/classes-and-courses) · [راهکار مدیریت باشگاه نکسورا](https://nexoura.ir/solutions/gym-management-software) · [راهکار رزرو مجموعه ورزشی کاروانا](https://karvana.ir/solutions/sports-booking-software/)

بنفش وقتیمو برای CTA و رنگ تیرهٔ برند برای عنوان‌ها استفاده می‌شود. سطوح مکمل لاوندر `#EDE9FE`، صورتی `#FCE7F3`، نعنایی `#D1FAE5` و آبی `#E0F2FE` از دامنهٔ سبک صفحات راهکار خارج نمی‌شوند. فاصله‌گذاری، ظرف صفحه، اندازه‌های متن و حالت فوکوس از توکن‌های موجود استفاده می‌کنند. تصاویر از دارایی‌های فعلی چهار کارت گرفته شدند. اطلاعات نمونهٔ Hero در HTML خواناست.

در موبایل، عنوان و دکمه‌ها پیش از تصویر قرار دارند. جدول زمان‌بندی استخر و نمای روزهای آکادمی به سطرهای خوانا تبدیل می‌شوند. وضعیت جای خالی و تکمیل ظرفیت با متن هم نمایش داده می‌شود. در دسکتاپ، نمای ظرفیت استودیو و برنامهٔ باشگاه در کنار توضیحات دیده می‌شوند و تقویم آکادمی و تابلوی سانس از عرض محتوایی استفاده می‌کنند.

## معماری و فایل‌ها

- مسیر پویا در [page.tsx](../../apps/web/src/app/solutions/%5Bslug%5D/page.tsx) فقط چهار اسلاگ مجاز را از دادهٔ تایپ‌شده تولید می‌کند. صفحهٔ جامع و اسلاگ خارج از فهرست پاسخ ۴۰۴ دارند. [layout.tsx](../../apps/web/src/app/solutions/layout.tsx) سبک صفحات راهکار را بار می‌کند.
- [industry-content.ts](../../apps/web/src/components/marketing/industry-content.ts)، [industry-page.tsx](../../apps/web/src/components/marketing/industry-page.tsx)، [industry-previews.tsx](../../apps/web/src/components/marketing/industry-previews.tsx) و [industry.css](../../apps/web/src/styles/industry.css) به‌ترتیب محتوا، اسکلت مشترک، نماهای تخصصی و چیدمان را نگه می‌دارند.
- فایل‌های مشترک تغییرکرده شامل `chrome.tsx`، `mobile-navigation.tsx`، `content.ts`، `demo.tsx` و `sample-data.ts` هستند. نمای ثابت محصول کامپوننت سرور است و تعامل دمو و منوی موبایل از کامپوننت‌های موجود استفاده می‌کند.
- در صفحهٔ اصلی، CTA باشگاه و سه کارت دیگر به مقصد صنعت خود می‌روند. ساختار تصویری کارت‌ها حفظ شده و کارت‌های ثانویه با لینک بومی فعال‌اند. تغییرات این بخش در `solutions-section.tsx`، `homepage.css` و آزمون مسیرهای جدید در `homepage.spec.ts` قرار دارند.
- `site-metadata.ts`، `robots.ts`، `sitemap.ts` و تنظیمات سراسری `app/layout.tsx` سیاست محیط انتشار را یکپارچه می‌کنند. تست‌های صفحات در [industry.spec.ts](../../apps/web/tests/industry.spec.ts) قرار دارند. وابستگی اجرایی دیگری برای این صفحات نصب نشد.

## سئو و انتشار

- هر صفحه H1 مستقل، عنوان و توضیح اختصاصی، Open Graph فارسی، مسیر خوانای صفحه و پیوند خزیدنی دارد. با دامنهٔ معتبر، Canonical، URL و تصویر کارت اجتماعی و دادهٔ ساختاریافتهٔ BreadcrumbList تولید می‌شوند. HTML اولیه، HTTP ۲۰۰، Canonical، Sitemap و Robots با یک دامنهٔ رزروشدهٔ آزمایشی روی بیلد محلی بررسی شدند.
- برای Build انتشار عمومی، `VAGHTIMO_SITE_URL` را با مبدأ HTTPS واقعی و `VAGHTIMO_INDEXABLE=1` را با تصمیم انتشار تنظیم کنید. محیط محلی و آزمایشی به‌صورت پیش‌فرض `noindex, follow` و Sitemap بدون URL دارند. دسترسی خزنده به HTML اجازه می‌دهد دستور noindex خوانده شود. در نبود دامنه، Canonical و URLهای مطلق ساخته نمی‌شوند.
- وضعیت منتشرنشدن تعرفه‌ها در متن پایانی آمده است. امکان ورود و رزرو واقعی در سایت عمومی به توسعهٔ جداگانهٔ ورود و اتصال به API نیاز دارد. نمایش دمو رویداد نوشتن به شبکه ارسال نمی‌کند.

## بازبینی بصری

هر چهار صفحه در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸، ۱۲۸۰ و ۱۴۴۰ پیکسل بازبینی شدند. تست Playwright امکان ثبت دوبارهٔ تصاویر را دارد. در بازبینی، نمایش شمارش ظرفیت باشگاه و جهت بازه‌های زمانی استخر اصلاح شد. رفتار نام لینک کارت‌ها پس از رفع نتیجهٔ axe دوباره آزموده شد.

## اعتبارسنجی عملکرد و دسترس‌پذیری

- بیلد production هر چهار مسیر را به HTML ایستا تبدیل کرد. lint و TypeScript موفق بودند. مجموعهٔ Chrome شامل ۲۳ تست بازگشتی و ۹ تست جدید بود و هر ۳۲ تست گذشتند. پاسخ مسیرها، مسیر بازگشت، دمو، FAQ، عدم ارسال درخواست نوشتن، صفحه‌کلید، خطاهای Console، منوی موبایل و سئو در آزمون پوشش داده شدند. [خروجی Chrome](evidence/industry/frontend-chrome.txt) · [خروجی lint](evidence/industry/frontend-lint.txt) · [خروجی TypeScript](evidence/industry/frontend-typecheck.txt)
- برای هر چهار صفحه عرض‌های ۳۲۰، ۳۶۰، ۳۷۵، ۳۹۰، ۴۱۴، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۴۴۰ و ۱۹۲۰ بررسی شدند. عرض سند با عرض صفحه برابر بود. axe در عرض‌های ۳۹۰ و ۱۴۴۰ برای همهٔ صفحات و صفحهٔ اصلی خطایی گزارش نکرد. ارزیابی دستی با صفحه‌خوان و بزرگ‌نمایی بومی مرورگر انجام نشده است.
- در Firefox و WebKit، هرکدام پنج تست متمرکز مسیر، دمو، کلیدها و HTML اولیه گذشتند. [خروجی Firefox](evidence/industry/frontend-firefox.txt) · [خروجی WebKit](evidence/industry/frontend-webkit.txt)
- ۸ تست مستقل دامنهٔ زمان‌بندی و ۶ تست مستقل دامنهٔ رزرو با موفقیت اجرا شدند. در مجموعهٔ کامل بک‌اند روی ویندوز، ۱۲۹ از ۱۴۴ تست واحد گذشتند و ۱۵ مورد مربوط به مجوزهای POSIX و اعتبارسنجی مسیر ابزار رد شدند. اجرای Integration پیش از آغاز تست، شمار فراخوانی‌های کامپایل‌شده را ناکافی گزارش کرد. پایگاه PostgreSQL ایزوله برای بازآزمایی در دسترس نبود. تطبیق SHA-256 نشان داد ۷۳۲ فایل ثبت‌شده خارج از محدودهٔ فرانت‌اند مطابق موجودی قبلی هستند. ### Lighthouse

بیلد محلی production با Chrome Headless 157 و Lighthouse 13.6.0 در شرایط شبیه‌سازی‌شده آزمایش شد. برای باشگاه در موبایل سه اندازه‌گیری و برای هر حالت دیگر یک اندازه‌گیری انجام شد. تصاویر Hero اندازهٔ مشخص، حاشیهٔ ثابت، `srcset` پاسخگو و بارگیری با اولویت بالا دارند. پس از اصلاح اولویت بارگیری، سنجش مجدد کشف و اولویت تصویر LCP را در همهٔ اجراها تأیید کرد. | باشگاه | ۹۲، میانهٔ ۹۲ / ۹۲ / ۹۷ | ۲٫۷۱ ثانیه، میانه | ۱۰۰ | ۰٫۶۰ ثانیه |

Accessibility، Best Practices و SEO در همهٔ اجراها ۱۰۰ و CLS برابر صفر بودند. دو اجرای موبایل باشگاه با زمان انسداد اصلی ۲۲۳ و ۲۳۴ میلی‌ثانیه، زیر هدف ۹۵ ماندند. در اجرای سوم زمان انسداد ۵۱ میلی‌ثانیه بود. LCP آزمایشگاهی موبایل در هر چهار صفحه بالاتر از ۲٫۵ ثانیه ثبت شد. INP و صدک ۷۵ از این آزمون‌های بارگیری به دست نمی‌آیند.

## وضعیت تحویل

| Gate | وضعیت | شواهد و محدودیت |
|---|---|---|
| A · صحت محصول | PASS | کنترلرهای جلسات و رزرو، قرارداد API و شناسهٔ «دادهٔ نمونه» در هر نما |
| B · هویت بصری | PASS | لوگو، فونت، هدر و فوتر مشترک و ۲۰ تصویر بازبینی‌شده |
| C · تجربهٔ کاربری | PASS | آزمون دمو، FAQ، کلیدها، بازگشت و مقصد کارت‌ها |
| D · پاسخگویی | PASS | ده عرض، کنترل اسکرول افقی و تصویر تمام‌صفحه در پنج عرض |
| E · سئوی فنی | PASS | HTML ایستا و آزمون فراداده، Canonical، BreadcrumbList، Robots و Sitemap در محیط آزمایش |
| F · دسترس‌پذیری | PARTIAL | axe و مسیر صفحه‌کلید گذشتند. صفحه‌خوان و زوم بومی در وضعیت NOT TESTED هستند. |
| G · عملکرد | PARTIAL | امتیاز موبایل باشگاه در میانه زیر هدف بود. معیارهای میدانی در وضعیت NOT TESTED هستند. |
| H · کیفیت مهندسی | PARTIAL | فرانت‌اند و تست‌های مستقل دامنه گذشتند. اجرای کامل بک‌اند با محدودیت محیط و خروجی کامپایل مواجه شد. |

## تصمیم‌های انتشار و کارهای بعدی

- ثبت رزرو واقعی، پنل ورود و انتشار تعرفهٔ رسمی تصمیم‌هایی مستقل از این صفحات هستند. دمو در تمام مسیرهای جدید با دادهٔ فرضی مشخص و تعامل محلی اجرا می‌شود.
- تعیین دامنهٔ نهایی و فعال‌سازی نمایه‌سازی به تنظیم Build انتشار وابسته است. نام دامنهٔ استفاده‌شده برای آزمون سئو فقط متعلق به همان بیلد محلی است.
- برای تأیید تجربهٔ کاربران واقعی، پس از انتشار باید LCP، INP و CLS در صدک ۷۵ اندازه‌گیری شوند. سنجش آزمایشگاهی معادل آن داده نیست.

## اجرای محلی

```powershell
cd apps/web
npm ci
npm run dev
```

نشانی پیش‌فرض `http://127.0.0.1:3000` است. برای بررسی مهندسی از `npm run lint`، `npm run typecheck` و `npm test` استفاده می‌شود. در ویندوز این اجرا از Chrome نصب‌شده با `PLAYWRIGHT_CHANNEL=chrome` استفاده کرد.
