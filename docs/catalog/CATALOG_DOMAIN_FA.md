# BookCore — مدل دامنه Catalog و Branch (Phase 05)

**وضعیت:** سورس پیاده‌سازی‌شده؛ تست مستقل NestJS/PostgreSQL هنوز اجرا نشده است.

- Branch و Service تحت یک Tenant قرار دارند. ارتباط `(tenant_id,id)` در جداول والد برای FK مرکب استفاده می‌شود. حذف فیزیکی فراهم نیست.
- ایجاد شعبه: نام trim شده ۲ تا ۱۲۰ حرف و آدرس اختیاری ۱ تا ۵۰۰ حرف؛ پاسخ `id/tenantId/name/address/active`.
- ایجاد خدمت: عنوان trim شده ۲ تا ۱۶۰ حرف، مدت پیش‌فرض ۵ تا ۱۴۴۰ دقیقه. مدت پیش‌فرض به معنی زمان قطعی Session نیست.
- مجوز ایجاد برای OWNER/MANAGER؛ فهرست برای OWNER/MANAGER/RECEPTIONIST/TRAINER سازمان فعال، در هر دو لایه HTTP و سرویسی؛ حد صفحه ۱ تا ۱۰۰، ترتیب و Cursor براساس UUID یکتا. Query نهایی دارای شرط عضویت فعال است.
- تمام mutationها با `UnitOfWork`, قفل سازمان، بازبینی AuthSession و Membership، و درج هم‌تراکنشی Audit/Outbox انجام می‌شوند. هویت Actor از Access Token معتبر است نه body.
- برای دیتای موجود که در Phase 04 با عنوان طولانی مجاز بوده، قیدهای جدید طول نام در Migration 006 با `NOT VALID` افزوده می‌شوند: نوشتن جدید باید معتبر باشد؛ ارزیابی داده‌های قدیمی پیش از `VALIDATE CONSTRAINT` نیازمند بررسی عملی است.

## سناریوی واقعی

یک سازمان دارای دو شعبه «مرکزی» و «غرب» است و خدمات مربی خصوصی و یوگا را تعریف می‌کند. این داده‌ها هنوز رزرو یا Session نمی‌سازند. فاز ۰۶ قبل از ساخت Session باید فعال‌بودن خدمت و شعبه، هم‌سازمانی‌بودن منابع و Availability را دوباره بررسی کند.
