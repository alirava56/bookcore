# طرح بازگشت و مدیریت شکست

روی پایگاه‌دادهٔ دارای Migrationهای افزایشی، صرفاً بازگردانی Image قدیمی با حفظ DB جدید ممکن است ناسازگار باشد. پیش از هر Release، ماتریس سازگاری نسخهٔ API/Worker/Schema و Snapshot معتبر داشته باشید. در وضعیت شکست: Readiness را false کنید، تراکنش‌های جدید را متوقف کنید، Workerها را Drain کنید، Manifest و Artifact دقیق را شناسایی کنید و فقط نسخهٔ سازگار API را برگردانید. در صورت نیاز به بازگشت داده، **تنها** پس از Restore تأییدشده در محیط ایزوله و تصمیم کسب‌وکاری دربارهٔ RPO اقدام کنید.

این طرح در Runtime آزموده نشده؛ Rollback ادعایی یا اجرای Production صورت نگرفته است.
